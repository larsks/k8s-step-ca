# step-ca Initialization Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the three-workload step-ca bootstrap/init/configure flow (a bootstrap Job pushing material to an external store, a separate init Job, and a post-init remote-admin configure Job) with a single initContainer on the step-ca Deployment that assembles a fully-configured `ca.json` before step-ca ever starts, with no remote administration and no built-in external-secret-store integration.

**Architecture:** One initContainer script (`init-step-ca.sh`) does everything: short-circuits if `ca.json` already exists; otherwise generates any missing `step-server-ca`/`step-provisioner-<name>` secrets via direct Kubernetes API calls (`kubectl`), runs `step ca init` with the operator-supplied RSA root (swapping in an RSA intermediate, since `step ca init` always generates an EC one), then uses `step`'s local-config-file mode (`--ca-config`, no running server) to add the `idrac` and `acme` provisioners, attach the RSA-only x509 template to `idrac`, and `jq`-edit the authority-level SAN policy and default certificate duration directly into `ca.json`. The Deployment's ServiceAccount gets RBAC to read/create/update Secrets in its own namespace so the initContainer can do this without a separate bootstrap workload.

**Tech Stack:** bash, `step` CLI (`docker.io/smallstep/step-ca` image, which bundles `step`, `bash`, and `jq`), `kubectl` (fetched at runtime, as `bootstrap-ca.sh` already does), `jq`, Kustomize, bats for script tests.

**Spec:** `step-ca-init.md`

## Global Constraints

- Root CA must be RSA; it is an error if `step-root-ca` contains an ECDSA certificate (`step-ca-init.md`, Certificate authorities).
- Certificate lifetime defaults to 90 days (2160h) for all provisioners (`step-ca-init.md`, Provisioners).
- Authority-level SAN policy: DNS allow `*.massopen.cloud` (multi-level wildcard), IP allow `10.0.0.0/8` (`step-ca-init.md`, Provisioners).
- `idrac` provisioner must reject certificate requests with a non-RSA key (`step-ca-init.md`, Provisioners) — enforced via `idrac-rsa.tpl`, already in the repo and unchanged by this plan.
- Remote administration (`step ca init --remote-management`) is disabled; all provisioner/template/policy configuration happens via local `ca.json` edits, never a running admin API (`step-ca-init.md`, Provisioners).
- `step-root-ca` is operator-supplied and never auto-generated; `step-server-ca` and `step-provisioner-<name>` are generated-if-absent and written back to the same secret name (`step-ca-init.md`, Certificate authorities / Provisioners).
- This repo does not assume or integrate an external secret store; Secrets are plain `Secret` objects, and any import/export via `ExternalSecret`/`PushSecret` is the operator's own concern, outside this repo (`step-ca-init.md`, Certificate authorities).

## Review Focus

- **`ca.json` already exists but a `step-provisioner-<name>` secret is later deleted or edited by mistake.** The script must not regenerate a new random password and silently create a mismatched secret — the `ca.json`-exists check must short-circuit *before* any secret-ensure logic runs, every time, not just on first init.
- **`step-root-ca` has been swapped to cert-only (per its documented lifecycle) and `ca.json` is then lost** (e.g. PVC recreated). The script must fail with a clear, actionable message telling the operator to restore `tls.key`/`password` to `step-root-ca`, not a confusing `step ca init` error about a missing file.
- **A `step-provisioner-<name>` or `step-server-ca` secret already exists with operator-supplied values** (not generated by this script). The generate-if-absent logic must use the existing secret's contents as-is and never overwrite it.
- **The pod is scheduled before `step-server-ca`/`step-provisioner-<name>` secrets exist.** Those volumes must be mounted `optional: true` so the pod can still start and the initContainer can generate them; `step-root-ca` must NOT be optional, since at minimum `tls.crt` must always be present.
- **A provisioner name collides with an authority-policy DNS pattern, or the policy block already exists in `ca.json`** (re-running after a partial failure). The `jq` policy edit must replace/merge cleanly rather than appending duplicate entries if ever re-run against a partially-built `ca.json`.

### Task 3: Secret generation and orchestration (`main`)

**Files:**
- Modify: `base/step-ca/init-step-ca.sh`
- Create: `tests/fixtures/fake-kubectl.sh` — a stub `kubectl` for the bats
  tests below. Must support exactly the invocations `ensure_server_ca`/
  `ensure_provisioner_password` make: `get secret <name> -o go-template=...`
  (reads from a flat `$FAKE_KUBECTL_SECRETS_DIR/<name>/<key>` layout,
  base64-encoded, matching real `kubectl`'s `-o go-template` output, or
  exits non-zero if the file is absent) and `apply -f -` (reads the
  manifest from stdin, extracts `metadata.name` and each `data.<key>` via
  `jq`/`yq` or a minimal parser, base64-decodes each value, and writes it
  to `$FAKE_KUBECTL_SECRETS_DIR/<name>/<key>`). Also appends every
  invocation's arguments to `$FAKE_KUBECTL_LOG` if that env var is set, for
  the "main exits 0... without touching secrets" test's assertion.

**Interfaces:**
- Consumes: `run_step_ca_init`, `add_idrac_provisioner`, `add_acme_provisioner`, `apply_authority_policy` (Tasks 1-2).
- Produces:
  - `ca_already_initialized(config_dir)` — returns 0 if `$config_dir/config/ca.json` exists.
  - `fetch_kubectl(workdir)` — downloads `kubectl` into `$workdir` (same technique as `bootstrap-ca.sh`), prints its path.
  - `secret_field(kubectl, namespace, secret, field, workdir)` — prints the decoded value of `field` from `secret`, or returns non-zero if the secret or field doesn't exist.
  - `ensure_server_ca(kubectl, namespace, workdir, root_crt, root_key, root_password_file)` — if the `step-server-ca` secret (checked via `secret_field`) is absent, generates an RSA intermediate signed by the root into `$workdir`, applies it as the `step-server-ca` Secret, and prints `$workdir/server_ca.crt:$workdir/server_ca.key`; if present, prints the mounted paths (passed in as the optional-volume mount point, e.g. `/step/server-ca/tls.crt:/step/server-ca/tls.key`).
  - `ensure_provisioner_password(kubectl, namespace, workdir, name, mounted_password_path)` — same generate-if-absent pattern for a single `step-provisioner-<name>` secret's `password` field; prints the path to use.
  - `main()` — the whole flow: exit 0 immediately if `ca_already_initialized`; otherwise fetch kubectl, resolve the root cert/key/password paths from `$STEP_ROOT_CA_DIR` (mounted `step-root-ca` secret, default `/step/root-ca`), failing with a clear message naming `step-root-ca` and telling the operator to restore `tls.key`/`password` if they are missing (see Review Focus), call `ensure_server_ca`, call `ensure_provisioner_password` for `server` and `idrac`, call `run_step_ca_init`, `add_idrac_provisioner`, `add_acme_provisioner`, `apply_authority_policy`, in that order. Reads `$STEP_CONFIG_DIR` (default `/home/step`) for where `ca.json` lives.

    `main()` is also the only place that reads the rest of the env var
    contract and forwards each value as the matching function argument
    (Task 4 wires these as container env vars; Task 3 just needs to read
    them with these exact names/defaults): `NAMESPACE` (no default,
    required — passed as the `namespace` argument to `ensure_server_ca`/
    `ensure_provisioner_password`), `STEP_CA_NAME` (default `SmallStep`,
    passed as `run_step_ca_init`'s `ca_name`), `STEP_DNS_NAMES`
    (comma-separated, passed as `dns_names`), `STEP_SERVER_PROVISIONER_NAME`
    (default `server`, passed as `provisioner_name` to `run_step_ca_init`
    and as `name` to the `server` call of `ensure_provisioner_password`),
    `STEP_IDRAC_PROVISIONER_NAME` (default `idrac`, passed as `name` to
    both `ensure_provisioner_password` and `add_idrac_provisioner`),
    `STEP_ACME_PROVISIONER_NAME` (default `acme`, passed as `name` to
    `add_acme_provisioner`), `STEP_POLICY_ALLOW_DNS` and
    `STEP_POLICY_ALLOW_IP` (passed to `apply_authority_policy` as
    `allow_dns`/`allow_ip`), and `STEP_DEFAULT_CERT_DURATION` (default
    `2160h`, passed as `apply_authority_policy`'s `default_duration`).
